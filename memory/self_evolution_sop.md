# 自我进化 SOP (Self-Evolution SOP)

> 如何通过 SOP 文档实现"文档即工具"的自我成长

---

## 1. 核心原理

| 原理 | 说明 |
|------|------|
| **文档即工具** | 写下的 SOP = 知识 + 执行能力 |
| **嵌入脚本** | 打破"知道但做不到"的壁垒 |
| **经验固化** | 一次成功 → SOP → 永久可复用 |

---

## 2. 成长循环 (AutoGPT 启发)

```
[学习] → [编写 SOP] → [执行验证] → [反思复盘] → [修订优化] → [复用积累]
    ↑                                                                            |
    └──────────────────────── 持续迭代 ◀─────────────────────────────────────────┘
```

**反思复盘** 是关键新增节点：执行后必须思考"这次和 SOP 预设有何差异？"

---

## 3. SOP 设计原则

### 3.1 质量标准

| 标准 | 要求 |
|------|------|
| **可执行** | 不是空话，必须能直接调用工具 |
| **可复用** | 不是一次性，必须能多次使用 |
| **自解释** | 不依赖外部说明，自身完整 |
| **有脚本** | 核心操作必须嵌入可执行代码 |

### 3.2 结构模板

```markdown
## 目标
一句话说明这个 SOP 要解决什么问题

## 前置条件
执行前必须满足的条件

## 执行步骤
1. ...
2. ...

## 典型坑点
- 避免方法...
- 常见错误...

## 嵌入脚本（如有）
```python
# Python 环境
```
```powershell
# PowerShell 环境
```
```javascript
# JavaScript 环境
```
```

### 3.3 命名规范

| 格式 | 用途 |
|------|------|
| `*_sop.md` | 方法论/流程文档 |
| `*.py` | 可执行工具脚本 |
| `*_sop_v*.md` | 带版本号的 SOP |

## 4. 嵌入脚本环境

### 4.1 语言运行时

| 语言 | 运行时 | 适用场景 | 调用方式 |
|------|--------|---------|---------|
| **Python** | python.exe | 数据处理、系统调用、复杂逻辑 | `code_run` |
| **JavaScript** | node.js | 服务端脚本、文件操作、工具链 | `code_run` |
| **TypeScript** | ts-node / bun | 类型安全脚本、原型开发 | `code_run` |
| **PowerShell** | powershell.exe | Windows 自动化、批处理 | `code_run` |
| **C#/.NET** | dotnet.exe | 跨平台 CLI、现代化工具 | `code_run` |

### 4.2 code_run 调用机制

| 参数 | 运行时 | 说明 |
|------|--------|------|
| `type="python"` | Python.exe | 数据处理、系统调用 |
| `type="powershell"` | powershell.exe | Windows 自动化 |
| `type` 未指定 | 默认 | 按脚本内容自动推断 |

### 4.3 本地环境状态

| 环境 | 版本 | 状态 |
|------|------|------|
| Python | 3.12 | ✅ 可用 |
| Node.js | 24.14 | ✅ 可用 |
| Bun | 1.3.10 | ✅ 可用 |
| .NET/C# | 9.0 | ✅ 可用 |
| PowerShell | 系统内置 | ✅ 可用 |
| Ruby/PHP/Java | - | ❌ 未安装 |

### 4.4 JS 运行时

| 运行时 | 特点 | 安装方式 |
|--------|------|---------|

## 5. 进化触发条件

满足以下任一条件时，应创建或更新 SOP：

| 触发 | 行动 |
|------|------|
| 成功完成一次复杂任务 | → 提炼为 SOP |
| 踩坑后找到解决方案 | → 记录为避坑指南 |
| 发现可复用的模式 | → 封装为工具脚本 |
| 现有 SOP 失效 | → 修订并标注版本 |

---

## 6. SOP 生命周期

```
[新建] → [使用] → [验证] → [反思] → [修订] → [归档]
              ↑                              ↓
              └────────── 持续迭代 ◀─────────┘
```

### 6.1 反思节点 (Reflexion 启发)

每次 SOP 执行后自问：

- 执行结果是否符合预期？
- 与预设步骤有何差异？
- 是否发现新的坑点需要补充？
- 这个 SOP 是否需要升级版本？

### 6.2 版本管理

```markdown
## v1.0 (2026-05-08) 初始版本
## v1.1 (2026-05-08) 增加反思机制
```

## 7. SOP 质量评估

| 指标 | 计算方式 | 目标 |
|------|---------|------|
| **完整性** | 有目标/步骤/脚本？ | ≥80% |
| **可执行率** | 有嵌入脚本的比例 | ≥60% |
| **复用次数** | 被调用执行次数 | 越多越好 |
| **成功率** | 一次执行成功的概率 | ≥85% |

## 8. 与 self_improving_sop 的区别

| 本 SOP | self_improving_sop |
|--------|-------------------|
| 目标：学会新方法 | 目标：不重复犯错 |
| 方式：写 SOP + 嵌入脚本 | 方式：追踪纠正 + 升级规则 |
| 触发：成功经验 | 触发：失败/纠正 |
| 关注：能力边界扩展 | 关注：错误率降低 |
